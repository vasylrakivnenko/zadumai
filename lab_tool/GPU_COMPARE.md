# Dedicated pod vs serverless (RTX 4090, Gemma 4 26B-A4B Q4_0, llama.cpp)

Generated by `analysis/gpu_compare.py`. Workload: 453 logged contract-review prompts (4 dev tasks; from the abandoned fixed pipeline), 4 in flight,
1,261,573 input + 187,919 output tokens = 1.45M tokens. Same image, flags and model file (network volume, EU-RO-1).

| setup | start to serving | workload | billed time | USD | USD / 1M tokens |
|---|---|---|---|---|---|
| dedicated pod, model on the network volume | 39 s | 704 s, 0 errors | billed 796 s | $0.164 | $0.113 |
| serverless flex worker (est.: our endpoint never served, see below) | 41 s (16 s image + 25 s model load, measured) | 704 s (same GPU, engine, flags) | est.: 755 s x $1.1/h | $0.231 | $0.159 |

Network volume (20 GB): $1.40 per month for either setup, on top.

Per hour of serving: dedicated $0.74 whether busy or idle; serverless $1.10 only while a worker is up (start + work + 10 s
idle). Serverless is cheaper only when the GPU would otherwise sit idle more than ~1/3 of the time (0.74 / 1.10 = 67% busy).
A task of 100-270 such calls keeps the GPU busy for 3-8 minutes, so per task: dedicated ~$0.05-0.10 if the pod is already up; serverless
~$0.07-0.16 including its ~40 s start, paid on every cold start.

## Serverless attempt (2026-10-06, EU-RO-1, load-balancer endpoint j8sh1gaz0yc9ya, deleted)
Two workers started and loaded the model (container start to `listening on 0.0.0.0:8080` in 25 s), but the load balancer
never routed a request to them (every request through https://<id>.api.runpod.ai hung; 12 minutes of polling). The first
worker was exited by Runpod after ~9.5 min; the second was stopped by us. Likely cause: the load balancer's health check
never passed (HEALTH_CHECK_PATH=/health on port 8080 was set as documented), not the model or GPU. Not resolved; the cost
of the failed attempt is $0.314 (1025 s billed).
